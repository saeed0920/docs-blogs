## 1. `if` / `else`

```js
if (score >= 90) {
  grade = "A";
} else if (score >= 80) {
  grade = "B";
} else {
  grade = "F";
}
```

Always use braces. A one-line `if` without braces is one careless edit away from a bug.

**Guard clauses beat nesting:**

```js
// ❌ arrow of doom
function pay(user) {
  if (user) {
    if (user.isActive) {
      if (user.balance > 0) {
        charge(user);
      }
    }
  }
}

// ✅ exit early
function pay(user) {
  if (!user) return;
  if (!user.isActive) return;
  if (user.balance <= 0) return;
  charge(user);
}
```

## 2. `switch`

For one value against many exact cases. Compares with `===`.

```js
switch (day) {
  case "sat":
  case "sun":
    console.log("weekend");
    break;
  case "mon":
    console.log("start");
    break;
  default:
    console.log("midweek");
}
```

<Callout type="warn">
Forget `break` and execution **falls through** into the next case. Stacked cases (`"sat"` above `"sun"`) use this on purpose; everywhere else it is a bug.
</Callout>

For simple value → value mapping, an object is shorter than a `switch`:

```js
const names = { sat: "Saturday", sun: "Sunday" };
const name = names[day] ?? "Unknown";
```

## 3. The loops

| Loop | Use when |
| --- | --- |
| `for (let i = 0; ...)` | You need the index, or a numeric range |
| `for...of` | You need the **values** of an array/string/Set/Map |
| `for...in` | You need the **keys** of an object. Never for arrays |
| `while` | Unknown count, condition-driven |
| `do...while` | Same, but must run at least once |

```js
const arr = ["a", "b", "c"];

for (let i = 0; i < arr.length; i++) console.log(i, arr[i]);
for (const item of arr) console.log(item);            // values
for (const key in { a: 1, b: 2 }) console.log(key);   // keys
arr.forEach((item, i) => console.log(i, item));       // no break possible
```

<Callout type="warn">
`for...in` on an array gives you **string** indices (`"0"`, `"1"`) and also walks inherited properties. Use `for...of` for arrays. Always.
</Callout>

```js
let n = 10;
while (n > 0) n--;

do {
  answer = ask();
} while (!answer);
```

## 4. `break` and `continue`

```js
for (const n of nums) {
  if (n < 0) continue;  // skip this one
  if (n > 100) break;   // stop the loop
  total += n;
}
```

Neither works in `forEach`, `map`, or `filter`. If you need to stop early, use a real loop — or `some`/`find`, which stop by design.

## 5. Nested loops and cost

```js
for (const a of listA) {
  for (const b of listB) {  // runs |A| × |B| times
    ...
  }
}
```

Two nested loops over the same data is O(n²). At 10 items nobody notices; at 10,000 the page freezes. In Phase 4 you replace most of these with a `Map` lookup. Notice them now.

## Traps recap

| Trap | Reality |
| --- | --- |
| `for...in` over an array | Gives string keys, includes inherited props |
| Missing `break` in `switch` | Falls through to the next case |
| `break` inside `forEach` | `SyntaxError` — use `for...of` |
| Modifying an array while looping it | Skipped elements. Build a new array instead |
| `while` with no change to the condition | Infinite loop. In the browser, a frozen tab |

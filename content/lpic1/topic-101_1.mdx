# System Architecture

Before you can administer a Linux system, you need to understand how it **discovers hardware**,
**boots**, and **transitions between runlevels/targets**. This topic (LPIC-1 101.1) covers hardware
configuration, the boot sequence, GRUB2, and controlling system state (shutdown, reboot, runlevels).

---

## Hardware discovery — `/proc` and `/sys`

Linux exposes live kernel and hardware information through two virtual filesystems.

| Filesystem | Purpose                                            |
| ---------- | -------------------------------------------------- |
| `/proc`    | Kernel/process runtime info (virtual, not on disk) |
| `/sys`     | Kernel's view of devices, drivers, and buses       |

```bash
cat /proc/cpuinfo        # CPU model, cores, flags
cat /proc/meminfo        # RAM usage details
cat /proc/interrupts     # IRQ assignments per device
cat /proc/ioports        # I/O port ranges in use
cat /proc/modules         # currently loaded kernel modules
cat /proc/cmdline        # kernel boot parameters used at startup
cat /proc/version        # kernel version string

ls /sys/class/net/        # network interfaces
ls /sys/block/            # block devices
cat /sys/class/dmi/id/product_name   # hardware/system model
```

`/proc` and `/sys` files are **not real files on disk** — they're generated by the kernel on read.

## Discovering devices — `lspci`, `lsusb`, `lsmod`

```bash
lspci                 # list all PCI devices
lspci -v              # verbose (driver in use, IRQ, etc.)
lspci -k              # show kernel driver bound to each device
lspci -nn             # show vendor:device IDs in brackets

lsusb                 # list all USB devices
lsusb -v              # verbose USB device tree
lsusb -t              # tree view (hubs and ports)

lsmod                 # list loaded kernel modules (reads /proc/modules)
```

### Managing kernel modules

```bash
modprobe e1000e         # load a module and its dependencies
modprobe -r e1000e       # remove a module (rmmod does this without deps)
rmmod e1000e             # remove a module directly (no dependency resolution)
insmod /path/to/mod.ko   # insert a module by exact file path (no dep resolution)
modinfo e1000e           # show module details: params, license, dependencies

# Module configuration
cat /etc/modprobe.d/blacklist.conf   # blacklist unwanted modules
echo "blacklist nouveau" >> /etc/modprobe.d/blacklist.conf
```

| Command    | Handles dependencies? | Typical use                  |
| ---------- | --------------------- | ---------------------------- |
| `modprobe` | Yes                   | Preferred way to load/unload |
| `insmod`   | No                    | Load one exact `.ko` file    |
| `rmmod`    | No                    | Remove one module directly   |

## BIOS vs UEFI

| Aspect             | BIOS (Legacy)             | UEFI                                         |
| ------------------ | ------------------------- | -------------------------------------------- |
| Firmware interface | 16-bit real mode          | 32/64-bit, can run before OS loads           |
| Partitioning       | MBR (max 4 primary parts) | GPT (up to 128 partitions)                   |
| Boot mechanism     | Reads boot sector (512B)  | Reads `.efi` files from EFI System Partition |
| Secure Boot        | Not supported             | Supported (verifies signed bootloaders)      |
| Boot menu          | Basic, text-only          | Graphical, mouse-capable                     |

```bash
# Check whether the system booted via UEFI or legacy BIOS
[ -d /sys/firmware/efi ] && echo "UEFI" || echo "BIOS (legacy)"

ls /sys/firmware/efi/efivars/   # UEFI variables (only exists in UEFI mode)
efibootmgr -v                   # list UEFI boot entries
```

## The boot process — step by step

```
Power On
   │
   ▼
1. Firmware (BIOS/UEFI) — POST, hardware init
   │
   ▼
2. Bootloader (GRUB2) — loads kernel + initramfs
   │
   ▼
3. Kernel — decompresses, initializes drivers, mounts initramfs
   │
   ▼
4. initramfs — temporary root FS; finds and mounts real root FS
   │
   ▼
5. init/systemd (PID 1) — starts targets/services
   │
   ▼
6. Login prompt / display manager
```

```bash
dmesg | less              # full kernel ring buffer (boot messages)
dmesg -T                  # with human-readable timestamps
journalctl -b             # boot log via systemd (current boot)
journalctl -b -1          # log from the previous boot
systemd-analyze           # time taken to boot
systemd-analyze blame     # which services took longest to start
systemd-analyze critical-chain   # the critical path of boot time
```

## GRUB2 — the boot loader

GRUB2 (GRand Unified Bootloader v2) is the near-universal Linux bootloader.

```bash
# Configuration files
/etc/default/grub              # high-level settings (edit this one)
/etc/grub.d/                   # scripts that generate the final config
/boot/grub/grub.cfg            # generated config (never edit directly)

# Regenerate grub.cfg after changing /etc/default/grub or /etc/grub.d/
grub-mkconfig -o /boot/grub/grub.cfg     # Debian/derivatives
update-grub                              # convenience wrapper (Debian/Ubuntu)
grub2-mkconfig -o /boot/grub2/grub.cfg   # RHEL/Fedora naming

# Install GRUB to a disk's MBR/boot sector
grub-install /dev/sda
```

### Key `/etc/default/grub` variables

```bash
GRUB_DEFAULT=0                 # which menu entry to boot by default
GRUB_TIMEOUT=5                 # seconds to show the menu
GRUB_CMDLINE_LINUX="quiet splash"   # kernel parameters appended at boot
```

### Editing boot parameters at boot time

At the GRUB menu, press `e` to edit an entry before booting — useful for:

```bash
# Boot into single-user/rescue mode by appending to the linux line
single
# or
systemd.unit=rescue.target
```

Press `Ctrl+X` or `F10` to boot the edited entry (not saved permanently).

## initramfs / initrd

A temporary, minimal root filesystem loaded into RAM, containing just enough
(kernel modules, `udev`, scripts) to find and mount the **real** root filesystem
(e.g. modules for RAID, LVM, or the disk controller).

```bash
lsinitramfs /boot/initrd.img-$(uname -r)     # list contents (Debian/Ubuntu)
update-initramfs -u                          # regenerate for current kernel
dracut --force                               # regenerate (RHEL/Fedora)
```

## init systems: SysVinit vs systemd

| Feature          | SysVinit                     | systemd                            |
| ---------------- | ---------------------------- | ---------------------------------- |
| PID 1 binary     | `/sbin/init`                 | `/usr/lib/systemd/systemd`         |
| States called    | **runlevels** (0–6)          | **targets** (`.target` units)      |
| Config location  | `/etc/inittab`, `/etc/rc.d/` | `/etc/systemd/system/`, unit files |
| Parallel startup | No (sequential)              | Yes                                |
| Service control  | `service`, `chkconfig`       | `systemctl`                        |

### SysVinit runlevels

| Runlevel | Meaning                            |
| -------- | ---------------------------------- |
| 0        | Halt (shutdown)                    |
| 1 / S    | Single-user (maintenance) mode     |
| 2        | Multi-user, no networking (Debian) |
| 3        | Multi-user, with networking (text) |
| 5        | Multi-user, with GUI (X11)         |
| 6        | Reboot                             |

```bash
runlevel               # show previous and current runlevel
init 3                 # switch to runlevel 3
telinit 5              # equivalent, older command name
cat /etc/inittab       # default runlevel config (legacy systems)
```

### systemd targets (the modern equivalent)

| Target              | Equivalent runlevel |
| ------------------- | ------------------- |
| `poweroff.target`   | 0                   |
| `rescue.target`     | 1                   |
| `multi-user.target` | 3                   |
| `graphical.target`  | 5                   |
| `reboot.target`     | 6                   |

```bash
systemctl get-default              # show default boot target
systemctl set-default multi-user.target   # set default target (persists)
systemctl isolate rescue.target    # switch target now (like init 1)
systemctl list-units --type=target # list all active targets
```

## Shutdown and reboot

```bash
shutdown -h now         # halt immediately
shutdown -r now         # reboot immediately
shutdown -h +10         # halt in 10 minutes
shutdown -c             # cancel a pending scheduled shutdown
shutdown -r 23:00       # reboot at a specific time

reboot                  # reboot immediately
halt                    # halt the system
poweroff                # power off the system

systemctl reboot        # systemd equivalent
systemctl poweroff       # systemd equivalent
systemctl halt           # systemd equivalent (halt, no power off)
```

`shutdown` (unlike `reboot`/`halt` directly) warns logged-in users and can be scheduled/cancelled — prefer it on multi-user systems.

| ------------------- | --------------------------------------- | ------------------------------------- |
| `lspci`             | List PCI devices                        | `-v` `-k` `-nn`                       |
| `lsusb`             | List USB devices                        | `-v` `-t`                             |
| `lsmod`             | List loaded kernel modules              | —                                     |
| `modprobe`          | Load/unload module + dependencies       | `-r`                                  |
| `insmod` / `rmmod`  | Load/remove one module directly         | —                                     |

| `journalctl`        | systemd logs incl. boot logs            | `-b`                                  |

| `systemd-analyze`   | Boot time analysis                      | `blame` `critical-chain`              |

| `systemctl`         | Manage/query systemd targets & services | `get-default` `set-default` `isolate` |
| `shutdown`          | Halt/reboot with warning & scheduling   | `-h` `-r` `-c` `+m`                   |

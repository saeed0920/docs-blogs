## مسئله

توی یک پروژه لیگسی لاراول که کاملاً روی Blade بنا شده، نیاز داشتم از آیکون‌های Iconify استفاده کنم. اما چند تا محدودیت داشتم:

- نمی‌خواستم پکیج‌های شخص ثالث (self-hosted service یا CDN) روی پروداکشن باشه.
- نمی‌خواستم روی سرور، مرحله build یا نصب اضافه اجرا بشه.
- کل دیتاست JSON آیکون‌ها (`@iconify/json`) خیلی سنگینه و فقط باید توی محیط development باشه (`-D`).
- می‌خواستم توی Blade به همون سادگی یک کامپوننت آیکون رو صدا بزنیم:

```blade
<x-icon name="mdi:home" />
```

## راه‌حل: یک پلاگین Vite

راه‌حل این بود که یک پلاگین Vite بنویسم که در زمان توسعه (dev / build)، فایل‌های Blade رو اسکن کنه، اسم آیکون‌های استفاده‌شده رو پیدا کنه، و برای هرکدام یک فایل SVG واقعی توی مسیر `storage/icons/{category}/{name}.svg` بسازه. روی پروداکشن هیچ نیازی به پکیج Iconify نیست؛ فقط یک سری فایل SVG استاتیک اونجا نشستن که مثل هر asset دیگه‌ای سرو می‌شن.

### نحوه‌ی تعریف پلاگین در Vite

```js
bladeIcons({
  patterns: [
    "resources/views/**/*.blade.php",
    "widgets/**/views/**/*.blade.php",
    "Modules/**/Resources/views/**/*.blade.php",
  ],
  output: "storage/icons",
  components: [{ tag: "x-icon", attr: "name" }],
  clean: true,
});
```

- **patterns**: مسیرهایی که باید برای پیدا کردن کامپوننت‌های آیکون اسکن بشن (چون پروژه ماژولار هست و چند تا مسیر Blade داره).
- **output**: مسیر خروجی فایل‌های SVG.
- **components**: تعریف اینکه دنبال چه تگ و چه attribute‌ای بگرده (اینجا `x-icon` با attribute `name`).
- **clean**: اگه true باشه، آیکون‌هایی که دیگه استفاده نمی‌شن به‌صورت خودکار حذف می‌شن.

## جریان کار پلاگین

1. **اسکن**: با `fast-glob` تمام فایل‌های Blade مطابق با patterns پیدا می‌شن.
2. **استخراج**: با یک regex ساده، مقدار `name="..."` داخل هر `<x-icon>` استخراج می‌شه (مثلاً `mdi:home`).
3. **بررسی وجود فایل**: قبل از هر چیز چک می‌کنه آیا `storage/icons/mdi/home.svg` از قبل وجود داره یا نه.
4. **تولید در صورت نیاز**: اگه فایل وجود نداشت، از `@iconify/json` و `@iconify/utils` استفاده می‌کنه تا SVG واقعی رو بسازه:

```js
const iconData = getIconData(set, name);
const svg = iconToSVG(iconData, { height: "auto" });
```

5. **نوشتن فایل**: SVG تولیدشده روی دیسک ذخیره می‌شه.
6. **پاکسازی (اختیاری)**: با `clean: true`، پلاگین دایرکتوری خروجی رو هم می‌گرده و هر SVG ای که دیگه توی هیچ فایل Blade ای استفاده نشده رو حذف می‌کنه.

## چرا این روش خوبه

- **بدون وابستگی روی پروداکشن**: پکیج‌های Iconify فقط `devDependencies` هستن. سرور پروداکشن اصلاً خبر نداره Iconify چیه؛ فقط یک پوشه پر از SVG می‌بینه.
- **بدون build اضافه روی سرور**: فایل‌های SVG از قبل، در زمان توسعه تولید و کامیت می‌شن (یا حداقل قبل از دیپلوی ساخته می‌شن). سرور فقط اونا رو سرو می‌کنه.
- **بدون سرویس شخص ثالث**: هیچ CDN یا API خارجی درگیر نیست؛ همه چیز self-contained و آفلاینه.
- **Cache طبیعی از طریق فایل سیستم**: چون چک می‌کنیم فایل از قبل هست یا نه، هر بار build فقط آیکون‌های جدید تولید می‌شن، نه همه چیز از اول.
- **HMR-friendly**: در `handleHotUpdate`، فقط فایلی که تغییر کرده دوباره اسکن می‌شه، نه کل پروژه — که برای پروژه‌های بزرگ لیگسی خیلی مهمه.

## نمونه‌ی ساده‌شده کد

```js
async function writeIcon(icon) {
  const dest = iconFilePath(icon); // storage/icons/mdi/home.svg

  try {
    await fsp.access(dest);
    return; // از قبل وجود داره، کاری نکن
  } catch {
    // وجود نداره، باید بسازیم
  }

  const svg = await generate(icon);
  if (!svg) return;

  await fsp.mkdir(path.dirname(dest), { recursive: true });
  await fsp.writeFile(dest, svg, "utf8");
}
```

## جمع‌بندی

با این پلاگین تونستم بدون هیچ تغییری توی معماری پروژه (همون Blade ساده)، از هزاران آیکون Iconify استفاده کنم، بدون اینکه پروداکشن به هیچ پکیج یا سرویس اضافه‌ای وابسته بشه. تنها چیزی که روی سرور می‌مونه، یک پوشه ساده از فایل‌های SVG استاتیکه!

اگه پروژه مشابهی دارید که محدودیت مشابهی روی وابستگی‌های پروداکشن داره، این الگو (تولید asset در dev-time + سرو استاتیک در production) می‌تونه خیلی جواب بده.
